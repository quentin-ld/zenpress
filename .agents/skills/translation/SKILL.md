# Translation

Two jobs wear this name and they have different tests.

**A string in a catalogue has a source text.** Equivalence can be judged: does
the French say what the English says, in the register the rest of the catalogue
uses, with the placeholders intact? This is checkable and mostly mechanical.

**Prose written fresh in French has no source.** There is nothing to be faithful
to, so the test is the writing test — see the `writing` skill. Do not run the
equivalence check on it; there is no other side to compare.

## The fleet's languages

**US English is the codebase language.** Every artefact in the repository is
English: identifiers, comments, docblocks, commit messages, `AGENTS.md`, the
harness's own docs. A French string belongs in exactly two places:

1. **A translation catalogue** — `languages/*.po`, generated by
   `bin/harness pot`. The source string is English; the French is the target.
2. **A reply to the owner**, who writes French and reads both.

Anything else in French is drift that the next reader pays for.

## Translating a string

Four things to check, in this order:

1. **Do not translate what WordPress translates.** `post`, `page`, `plugin`,
   `dashboard`, `customize` are menu labels and interface terms. If WordPress
   already renders it in French for this user, translating it again produces a
   page where the same concept has two names.
2. **Placeholders survive verbatim.** `%s`, `%d`, `%1$s`, `{name}`. WordPress
   uses positional placeholders precisely so a translation may reorder them;
   reordering is expected, changing is a bug.
3. **The register matches the catalogue.** WordPress's own French is formal
   (`vous`, `Veuillez`), and a plugin whose strings alternate between `tu` and
   `vous` reads as machine output.
4. **Plural forms.** French and English both have two, but the boundary sits
   differently: English `1 item / 2 items`, French `1 article / 2 articles`,
   with zero taking the singular in French and the plural in English. `_n()` and
   `_nx()` exist for this; a hand-written plural will get it wrong.

## French specifics

- **Non-breaking space before `: ; ! ?`.** French typography requires it, and a
  missing one is the detail a French reader notices first.
- **Capitalisation.** French does not title-case headings: `Gestion des
  licences`, not `Gestion Des Licences`.
- **False friends that appear in this domain.** `librairie` is a bookshop, a
  library is `bibliothèque` (and a code library is `bibliothèque` or left as
  `library`). `éventuellement` means "possibly", not "eventually"
  (`finalement`). `actuellement` means "currently", not "actually" (`en fait`).
  `sensible` means "sensitive", not "sensible" (`raisonnable`).
- **`Gutenberg`, `WordPress`, product names** do not get translated or
  inflected.

## Reviewing an existing translation

Read the French alone first, without the English beside it. If it does not read
as a sentence a French speaker would write, the problem is already visible and
comparing will not help. Then compare for the four checks above.

## Where the string lives

`bin/harness pot` regenerates the catalogue from the source. Never edit a `.po`
by hand and never hand-write a `.mo`: the next `make:pot` overwrites both. The
only file worth editing is the source string, and if the English is wrong it is
wrong in every language.
